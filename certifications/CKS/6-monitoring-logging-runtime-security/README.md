### Falco - from sysdig https://www.sysdig.com/opensource/falco

- `User Space / `Kernel Space`
- one way: `Falco Kernel Module` - inside the `Kernel Space` - managed K8S providers don't allow this
- other way: `eBPF` (Extended Berkeley Packet Filter) 
- `systems calls` are then analysed by the `sysdig libraries` in the `User Space`
- `the events` are then filtered by the `Falco Policy Engine` making use of the predefined `Falco Rules`
- `suspecious events` are the moved to various outputs - email alert, slack channel
- Two ways to install:
  - If you install Falco as a package this will also install the `Falco Kernel Module`
  - Install as a daemonset on the K8S cluster using helm

### Using Falco for threat detection

```bash
# check if falco was installed as a package on the host
$ systemctl status falco
# inspect the events generated by the falco service 
$ journalctl -fu falco
# if you open a shell in an nginx container you should see an event: A shell was spawned in a container ...
```

- Default Rules Files: https://falco.org/docs/concepts/rules/default-custom/

### Immutability - mount container's root filesystem as read-only.

```yaml
# make the whole root file system read only 
securityContext:
  readOnlyRootFilesystem: true
...

# limit the read only to a specific volume
volumeMounts:
  - mountPath: /mnt/volume1
    name: volume1
    readOnly: true
```

```bash
# create k8s cluster
$ k3d cluster create

$ k apply -f nginx-read-only-container.yaml

# check the logs
$ k logs -f nginx-read-only-container
/docker-entrypoint.sh: Launching /docker-entrypoint.d/10-listen-on-ipv6-by-default.sh

$ kubectl get pods

# echo foo > /mnt/path2/foo.txt
```
